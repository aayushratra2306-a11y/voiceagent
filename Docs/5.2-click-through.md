# 5.2 Invitations — local click-through

For you to run by hand once you're ready to test, before we deploy. Needs
a running backend, a running frontend dev server, and one real account
that already exists (any account from earlier testing works). Nothing
here is automated.

## Start the backend

From `backend/`, with the virtualenv already set up and `backend/.env`
already configured:

```bash
cd "D:\Voice Agent\backend"
venv/Scripts/uvicorn main:app --reload --port 8080
```

## Start the frontend

From `frontend/`, in a second terminal:

```bash
cd "D:\Voice Agent\frontend"
npm run dev
```

Open the URL it prints (usually `http://localhost:5173`).

## Check 1 — inviting doesn't reveal whether an address is registered

1. Sign in as your existing account. Go to **Members** for any organisation
   you own or admin.
2. Invite `definitely-not-a-real-account-12345@example.com`.
3. **Expect:** "Invitation created. Nobody has been notified — copy this
   link and send it to them yourself." with a copyable link and an
   expiry date. **Not** an error, **not** "no account found."
4. Invite an email address you know already has an account. **Expect:**
   the exact same message and shape — no visible difference.

This is the security fix 5.2 exists for. If step 3 or 4 ever look
different from each other, something has regressed.

## Check 2 — the link actually works, for someone new

1. Copy the link from Check 1 (the unreal address one is fine to reuse,
   or invite a fresh throwaway address).
2. Open the link in a **private/incognito window** (so you're not signed
   in as yourself).
3. **Expect:** a preview showing the organisation name, the role offered,
   who invited you, and which address the invitation is for.
4. Click **Sign up**, register with the invited email address (the page
   shows you which address the invitation is for).
5. **Expect:** "Account created! Please sign in." — registering does not
   sign you in. Sign in with the same address.
6. **Expect:** now you land back on the invitation (not on the normal
   dashboard) and can click **Accept invitation**.
7. **Expect:** after accepting, you're taken into that organisation's
   dashboard.
8. Back in your normal window, refresh the Members page. **Expect:** the
   new person now appears in the members list with the role you gave
   them, and is gone from the pending-invitations list.

## Check 3 — a revoked link stops working

1. Invite another throwaway address.
2. On the Members page, find it in the pending list and click **Revoke**.
3. Open the invite link in a private window.
4. **Expect:** "This invitation link is no longer valid." — the same
   message an invite that was never real would give.

## Check 4 — an expired link behaves the same as a revoked one

Invitations expire after 7 days, so you can't wait one out by hand. Skip
this in the click-through; it's covered by an automated test
(`test_an_expired_invitation_is_not_found` in
`backend/tests/test_invitations_service.py`) instead.

## Check 5 — the wrong account can't accept someone else's invitation

1. Invite `check5@example.com` (a throwaway address you won't register).
2. While signed in as your OWN account (a different email), open the
   invite link.
3. **Expect:** "This invitation was sent to check5@example.com, which
   isn't the account you're signed in with," with a **Sign out and use a
   different account** button. Not an Accept button that would then fail.

## Check 6 — an admin can't be pushed around by another admin

Only relevant if you have two admin-or-above accounts to test with.

1. As an owner, invite someone as **owner**.
2. As an **admin** (not owner), open the pending-invitations list.
3. **Expect:** no Revoke button next to that invitation. (An admin
   revoking an owner invitation is refused server-side; the UI now
   matches that rather than offering a button that would fail.)

## Check 7 — deleting an organisation kills its invitations too

1. Create a second organisation you own, and invite someone to it.
2. Delete that organisation (Settings → Delete, only possible if it has
   no bots/webhooks/pending approvals and isn't your only org).
3. Open the invite link you just created.
4. **Expect:** "This invitation link is no longer valid." — not a crash,
   and no membership silently appearing in a deleted organisation.

## Check 8 — losing your rights takes your invitations with you

Needs two accounts: you as owner, and a second account you make an admin.

1. As the **admin** account, invite a throwaway address.
2. As the **owner**, demote that admin to **viewer** (or remove them).
3. Open the invite link the admin created.
4. **Expect:** "This invitation link is no longer valid."

An invitation hands out a role. If the person who sent it loses the right
to hand out roles, their outstanding invitations must stop working — not
keep granting access for the rest of the 7 days.
