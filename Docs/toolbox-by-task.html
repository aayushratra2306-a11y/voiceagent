Part one

The platforms, in plain words

Ten outside services do work this project would otherwise have to do itself. Each one below: what it is, what it does here, and why it and not something else.

Deepgram

Speech → text

Turns the caller's voice into written words, live, as they speak.

Words appear while the sentence is still being said rather than after it finishes — which is what makes a reply possible in under a second. Handles Indian-accented English and Hindi well, and lets us control how long a pause must be before it decides a sentence has ended.

Pre-paid credits · local Whisper available as a free substitute

Cartesia

Text → speech

Reads the bot's reply out loud in a human-sounding voice.

Chosen because it starts speaking in about a tenth of a second — most rivals take noticeably longer, and on a phone call that gap is dead air. It also speaks Hindi, French, German and Spanish with genuine native voices rather than an English voice reading foreign words.

Credits per character spoken · Piper is the free local substitute

Groq

The AI brain

Decides what the bot should actually say.

Not a model of its own — it runs open models on purpose-built chips. The same model that takes about 400 milliseconds to start replying elsewhere starts in roughly 80 here. In a conversation that is the difference between natural and stilted.

Free tier, generous limits

OpenAI

Embeddings + rewriting

Converts documents into numbers a computer can search by meaning.

Used for two narrow jobs, not for conversation: turning uploaded documents into searchable form, and tidying spoken questions before searching. Also available as the alternative brain if Groq is ever unsuitable.

Pay per use, very small amounts

Pinecone

Document search

Stores uploaded documents so the right passage can be found in milliseconds.

Holds two separate indexes: one that searches by meaning, one that searches for exact words like order numbers. It also scores how relevant each result really is, which is what makes it possible to say "nothing in your documents answers this" instead of guessing.

Free tier · 500 relevance checks per month

MongoDB Atlas

The database

Remembers everything: users, bots, conversations, uploaded files.

A hosted database, so there is no database server to maintain. Original PDFs are stored inside it too, which is how a citation can open the actual document at the right page.

Free tier, permanently

Google Cloud

The server

The actual computer everything runs on, in Mumbai.

An ordinary virtual machine rather than a modern app-hosting service — deliberately. Live audio needs network access that hosts like Vercel and Render do not permit, so this project has to run its own machine.

Free trial credit until 30 November 2026

Sentry

Error tracking

Tells you when something breaks, without you having to look.

Every crash is captured with the full context of what led to it. Two separate projects — one for the server, one for the browser — because they fail in completely different ways.

Free tier

Langfuse

AI monitoring

Shows what the AI did on every call, and what it cost.

Records each step of every conversation — how long the AI took, how many words it processed, what that was worth in rupees. Hosted in Europe, chosen so the data-residency question has a clean answer.

Free hobby tier with a hard cap — it can never bill you

GitHub Actions

Automated checking

Runs every test automatically each time code changes.

Five checks on every push: code style, the full test suite, known security holes in dependencies, accidentally committed passwords, and document-search accuracy. Nothing reaches the main branch without passing.

Free for this usage

Phase 1 — Foundation Quality

Eight tasks making the conversation itself good: natural turn-taking, fast replies, the ability to take actions, and document search that finds the right thing.

1.1

Smart Turn detection + interruptions

3h

Teaching the bot when the caller has actually finished speaking, and letting the caller cut in mid-sentence without the bot ploughing on.

Plan specified
pipecat-ai[smart-turn]Smart Turn v2 PipelineParamsVADParams
Actually used
pipecat-ai[local-smart-turn]Smart Turn v3.2 (ONNX) SileroVADAnalyzerVADParams LLMUserAggregatorParams
What these are
pipecat-ai[smart-turn]
The voice framework, installed with its optional turn-detection extra. The square brackets are Python's way of saying "also install the parts needed for this feature".
Smart Turn v2 / v3.2
A small AI model that listens to how a sentence trailed off and judges whether the person is finished. We use v3.2 as a local file, so the decision costs no network trip.
ONNX
A universal format for AI models, so one file runs anywhere without the framework it was trained in. It is why turn detection runs on the server with no GPU.
PipelineParams
Pipecat's settings object for the pipeline as a whole. The plan expected the speech detector to attach here — it does not, and passing it here was silently ignored.
VADParams
The four dials on speech detection: how confident, how loud, how long before "started", how long before "stopped". Tuning these is what stops it mishearing a fan as a voice.
SileroVADAnalyzer
The actual speech detector — an ML model that scores every fragment of audio for how likely it is to be human speech.
LLMUserAggregatorParams
The settings for the component that collects a caller's words into one complete turn. In Pipecat 1.7 the speech detector attaches here, which is the whole lesson of this task.
Changed: v3 shipped by the time we built it, and it runs as a local ONNX file rather than a service. More importantly, in Pipecat 1.7 the speech detector attaches to the conversation aggregator, not to PipelineParams as the plan assumed — passing it the old way was silently ignored and none of the tuning applied.
1.2

Switch the AI to a faster provider

2h

Moving the thinking part of the bot onto hardware that starts replying in about a fifth of the time.

Plan specified
Groq APILlama 3.3 70BCerebras (alt)
Actually used
Groq APIopenai/gpt-oss-120b reasoning_effort=lowGroqLLMService
What these are
Groq API
Not an AI model — a company running open models on custom chips built for speed. Same model, roughly a fifth of the waiting time.
Llama 3.3 70B
Meta's open model, what the plan named. Perfectly good; simply superseded by a better option on the same platform.
Cerebras
A rival speed-focused chip company, listed as a backup. Never needed.

The model actually used — an open-weights model, larger and stronger than the planned one, at the same speed on Groq.
reasoning_effort=low
A dial telling the model how long to think before answering. Thinking improves answers and costs seconds — seconds a phone call does not have.
GroqLLMService

1.3

Build the function-calling framework

5h

Letting the AI actually do things — look up an order, book a slot — rather than only talk about them.

Plan specified
OpenAI function callingFunctionSchema register_functionPydantic
Actually used
Pipecat direct functionsPython type hints Docstrings as descriptions
What these are
OpenAI function calling
The industry-standard way of describing a tool to an AI so it can decide to use it. Groq and others follow the same format.
FunctionSchema
A hand-written description of a tool — its name, what it does, what inputs it needs. The plan assumed we would write these by hand.
register_function
The older way of telling the framework "this description maps to this code". No longer needed in Pipecat 1.7.
Pydantic
Python's data-checking library. It verifies that what arrives is the right shape before your code touches it — used everywhere in this project.
Direct functions
Pipecat 1.7's approach: write a normal Python function, and it reads the description straight from your type hints and docstring.
Type hints
Python annotations saying what kind of value each input is (date: str). The framework turns these into the tool description automatically.
Docstrings
The description written inside a function. Here it becomes the text the AI reads to decide when to use that tool — so its wording genuinely matters.
Simpler than planned: Pipecat 1.7 reads a plain Python function's type hints and docstring and builds the schema itself. No FunctionSchema, no register_function — writing the function and listing it is the whole registration.

1.6

Rewrite spoken questions before searching

2h

People speak differently from how they type. "Umm, what about the second one" is not a search query.

Plan specified
Groqgpt-4o-mini (alt)
Actually used
Groq gpt-oss-20bSkip heuristic
What these are
gpt-oss-20b
A deliberately small, fast model. This job is tidying a sentence, not reasoning — a bigger model would only add delay.
gpt-4o-mini
OpenAI's small model, the listed alternative. Groq's was faster for the same quality.
Skip heuristic
A simple word list that recognises small talk. "Hello" and "thank you" skip document search entirely, saving about two seconds.
As planned, plus an addition: conversational filler ("hello", "thanks") now skips document search entirely, saving about two seconds on those turns.
1.7

Add reranking to document search

3h

Fetching many possible answers, then having a second model actually read each one against the question and rank them properly.

Plan specified
Cohere Rerankbge-reranker (free)Pinecone
Actually used
bge-reranker-v2-m3Hosted by Pinecone top_k 20 → top_n 4
What these are
Reranking
Fetching many possible answers cheaply, then having a second model read each one against the question and score real relevance.
Cohere Rerank
A paid reranking service, the plan's first suggestion. Avoided — it would have meant another vendor and another bill.
bge-reranker-v2-m3
The open reranking model actually used, running inside Pinecone so no extra account was needed.
top_k 20 → top_n 4
Cast a wide net of 20 candidates, then keep only the 4 the reranker rates highest. Wide net, strict filter.
Threshold 0.15
The score below which a result counts as irrelevant. Possible only because reranked scores spread out; raw similarity scores cluster too tightly to draw a line.
Changed: the reranker runs inside Pinecone, so Cohere never became a separate account, bill or point of failure. The proof it works: for one real question the correct page did not even reach the top five by ordinary search, and reranking placed it first.
1.8

Add keyword matching alongside meaning matching

1h

Searching by meaning misses exact strings — order numbers, part codes. Keyword search finds those directly.

Plan specified
Pinecone sparse-denseBM25
Actually used
Two separate indexesvoiceagent + voiceagent-sparse Union, then rerank
What these are
Dense search
Searching by meaning. "Refund policy" finds "money back" even with no shared words.
Sparse / keyword search
Searching for exact strings. This is how order numbers and part codes get found — meaning-based search represents them poorly.
BM25
The long-standing formula behind keyword search, weighing how rare a word is against how often it appears.
Two indexes
Pinecone's indexes hold one search type or the other, never both — confirmed by querying it directly. Hence one of each, searched together and merged.
Changed by necessity: the plan assumed one index could hold both kinds of search. Checking Pinecone directly proved otherwise — their indexes are one type or the other. So there are two, searched at once and merged before ranking.

Ten tasks making it a system rather than a demo: no vendor it cannot leave, no crash that takes everything down, and proof that it works.

2.1

Build the provider switching layer

5h

Nothing calls a vendor directly. One file decides which speech, voice and AI service to use, so swapping any of them is a setting.

Plan specified

Actually used

What these are
pydantic-settings
Reads configuration from environment variables and checks it is valid at startup, so a missing key fails immediately rather than mid-call.
Factory pattern
A function that hands back the right object for the current configuration. Ask for "the speech service" and get Deepgram or Whisper depending on one setting.
Protocol / ABC
Two Python ways of saying "anything used here must have these methods". Not needed — the factory functions were enough on their own.
providers.py
The one file that knows which vendors exist. Everything else asks it for a service and never names a vendor.
As planned. This is the single most valuable decision in the project — it is what makes "what if a vendor raises prices" a five-minute answer instead of a rewrite.

2.3

Self-host the call connection server

5h

Running the live-audio infrastructure yourself instead of paying a service per minute of conversation.

Plan specified
LiveKit self-hostedOracle Cloud free tier Dockercoturn
Actually used
Pipecat SmallWebRTCaiortc 1.15 coturnCaddy Docker ComposeGoogle Cloud
What these are
WebRTC
The browser technology for live two-way audio — the same thing video calls use. The only realistic option for real-time voice on the web.
LiveKit
A separate server for managing live audio, the plan's choice. Dropped: Pipecat carries its own, so this was an entire extra system to run for nothing.
aiortc
The Python library implementing WebRTC on the server side, so Python can be one end of a live call.
coturn
A relay for callers whose network blocks direct connections — corporate firewalls and many mobile networks. Without it those callers simply cannot connect.
Caddy
A web server that obtains and renews HTTPS certificates automatically. Required, not optional: browsers refuse microphone access without real HTTPS.
Docker Compose
Describes all the pieces — app, relay, web server — in one file so the whole system starts with a single command.
Significantly changed: LiveKit was unnecessary — Pipecat carries its own WebRTC transport, removing a whole extra server. Google Cloud over Oracle for the free credit, and Caddy was added because browsers refuse microphone access without real HTTPS.
2.4

Give every call its own process

5h

Each conversation runs in its own isolated program, so one crashing cannot affect any other.

Plan specified
multiprocessingsubprocessDocker containers
Actually used
multiprocessing (spawn)Queues for messaging Pre-warmed worker pool
What these are
multiprocessing
Python's way of running genuinely separate programs, each with its own memory. A crash in one cannot touch another.
spawn vs fork
Two ways to start a process. Linux defaults to fork, which inherits the parent's memory — including a database connection that no longer works. Forcing spawn everywhere fixed every call failing on first deploy.
Queues
How the main server and a call process pass messages, since they share no memory.
Worker pool
Processes started before anyone calls, so the caller never waits for one to boot. Setup went from 13.7 seconds to 0.04.
The production lesson: Linux starts new processes differently from Windows by default, and that difference broke every call on first deploy. Forcing the Windows behaviour everywhere fixed it. A pool of pre-started workers was added later, cutting call setup from 13.7 seconds to 0.04.
2.5

Harden login security

4h

Short-lived login tokens, the ability to revoke a stolen one, and limits on how often anyone can try.

Plan specified
python-joseRedis slowapihttpOnly cookies
Actually used
python-jose 3.5MongoDB revocation list slowapi 0.1.10httpOnly refresh cookie bcrypt
What these are
JWT
A signed token proving who you are, which the server can verify without a database lookup. Ours expires after 15 minutes.
python-jose
The library that creates and verifies those tokens.
Refresh token
A longer-lived second token that quietly gets you a new 15-minute one, so short expiry does not mean logging in constantly.
httpOnly cookie
A cookie JavaScript cannot read. It means a script injected into the page still cannot steal the refresh token.
Redis
A fast in-memory store, planned for tracking revoked logins. Replaced by MongoDB — same result without running a second database for one small list.
slowapi
Rate limiting: caps how many times an address or account can try an action, which is what stops password guessing.
bcrypt
The algorithm that stores passwords in a form nobody can reverse, deliberately slow so guessing is impractical.
Changed: MongoDB instead of Redis for tracking revoked logins. Functionally identical here, and it avoided running an entire extra database for one small list.

2.8

Build a document search test suite

3h

Thirty-two real questions with known answers, so a change that quietly makes search worse is caught immediately.

Plan specified
pytestA representative test PDF
Actually used
pytest32-question set Baseline 28/32Regression floor 24/32
What these are
pytest
Python's testing tool. The whole suite runs in about 25 seconds, which is what makes it worth running constantly.
Regression floor
The test asserts 24 of 32 rather than all 32. Normal variation then passes while a genuine drop still fails — a test that cries wolf gets ignored.
As planned. The floor matters: the test asserts a margin rather than perfection, so ordinary variation does not cause false alarms while a real regression still fails.
